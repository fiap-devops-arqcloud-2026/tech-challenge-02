Kubernetes Básico

A fundação do Kubernetes em 7 aulas: o que é, suas peças, e como se põe uma aplicação no ar — com o significado de cada sigla e um exemplo real do nosso projeto.

Guia de estudo7 aulas+ glossário de siglas+ conexão com o ToggleMaster

O que é Kubernetes?

É o "maestro" que organiza aplicações empacotadas em containers: decide onde cada uma roda, reinicia o que quebra e cria mais cópias quando o movimento aperta. Apelido: K8s (K + 8 letras + s).

Por que combina com o nosso projeto

Este módulo é a fundação de todos os nossos manifestos (a pasta infra/k8s/). Cada peça que ele ensina — Pod, Deployment, Service, ConfigMap, Secret, Ingress, StatefulSet, HPA — existe de verdade no ToggleMaster.

Glossário — o significado das siglas

Todos os termos e siglas que aparecem nas aulas, em uma linha cada.

K8sKubernetesO "maestro" que organiza os containers.
ClusterO conjunto de máquinas que o Kubernetes gerencia como se fossem uma só.
Control PlaneO "cérebro/gerência" do cluster: toma as decisões.
Worker Nodenó de trabalhoA máquina que de fato roda os seus apps (os pods).
API ServerA "recepção central": recebe todos os comandos do cluster.
etcdO "banco de memória" onde o Kubernetes guarda o estado de tudo.
SchedulerO "planejador" que escolhe em qual nó cada pod vai rodar.
kubeletO agente que roda em cada nó e executa o que o cérebro mandou.
PodA menor "caixinha" do Kubernetes; roda 1 container (às vezes poucos).
DeploymentO "gerente" que mantém os pods no ar, recria os que caem e atualiza versões.
ReplicaSetQuem garante o número certo de cópias (réplicas) de um pod. O Deployment usa ele.
ServiceUm "endereço fixo" para achar os pods (que vivem mudando de IP).
ClusterIPO tipo de Service que só é visível dentro do cluster (interno).
ConfigMapGuarda configurações NÃO secretas (portas, URLs).
SecretGuarda dados sensíveis (senhas, chaves) — o "cofre".
IngressA "portaria" que recebe URLs de fora e roteia para o serviço certo.
NamespaceUma "pasta" dentro do cluster que separa os recursos de um projeto.
kubectlO "controle remoto": o comando que você usa para falar com o cluster.
ManifestoO arquivo YAML que descreve o que você quer (o pod, o service…).
Minikube / KindFerramentas para rodar um Kubernetes de mentira no seu notebook (estudo).
ProbesondaChecagem de saúde: readiness ("está pronto?") e liveness ("está vivo?").
PV / PVCPersistent Volume / ClaimO "HD virtual" persistente (PV) e o "pedido" desse HD (PVC).
StorageClassO "tipo de disco" que o cluster cria automaticamente (na AWS, um volume EBS).
StatefulSetComo um Deployment, mas para apps COM estado (bancos), com disco fixo.
HPAHorizontal Pod AutoscalerCria/remove pods automaticamente conforme o uso de CPU.
EKSElastic Kubernetes ServiceO Kubernetes gerenciado da AWS (onde subimos o projeto).

As 7 aulas, uma a uma

Cada ficha tem o mesmo esqueleto: em palavras simples, para que serve, um caso de uso e a conexão com o ToggleMaster.

01

Introdução e Arquitetura do Kubernetes

Usamos no projeto
Em miúdos
O que é o Kubernetes, o que é um cluster e por que ele virou o padrão para rodar apps em containers em escala.
Para que serve
Automatizar a implantação, o "conserto" e o crescimento de aplicações — sem fazer tudo na mão.
Caso de uso
Uma empresa com dezenas de microsserviços usa o Kubernetes para manter todos no ar e escalar sob demanda.
No ToggleMaster
Rodamos tudo no EKS (o Kubernetes da AWS) — 5 microsserviços orquestrados num cluster.
02

Control Plane e Worker Nodes

Usamos no projeto
Em miúdos
As duas "metades" do cluster: o Control Plane (o cérebro/gerência) e os Worker Nodes (as máquinas que fazem o trabalho).
Siglas e termos
No cérebro: API Server (recepção), etcd (memória), Scheduler (planejador). Nos nós: kubelet (o agente executor).
Para que serve
Separar quem DECIDE de quem EXECUTA — o que dá resiliência e escala.
Caso de uso
Um nó cai; o cérebro percebe e recria os pods daquele nó nos que sobraram.
No ToggleMaster
A AWS cuida do Control Plane (a gente nem vê); criamos só os 2 worker nodes (c7i-flex.large) onde os pods rodam.
03

Preparando o Ambiente e Primeiro Contato

Usamos em parte
Em miúdos
Como montar um Kubernetes para estudar (Minikube/Kind, no notebook) e o kubectl — o comando com que se fala com o cluster.
Siglas e termos
Minikube, Kind (Kubernetes in Docker), Docker Desktop, kubectl, kubectl get/apply/describe.
Para que serve
Praticar Kubernetes sem custo e aprender a ferramenta principal do dia a dia.
Caso de uso
Rodar um cluster de mentira no notebook com o Kind e testar manifestos antes de ir pra nuvem.
No ToggleMaster
Usamos bastante o kubectl (para aplicar tudo e depurar). Não usamos Minikube/Kind — fomos direto para o EKS na nuvem.
04

Rodando a Primeira Aplicação: Pods e Deployments

Usamos no projeto
Em miúdos
O Pod é a menor "caixinha" que roda um container. O Deployment é o "gerente" que mantém os pods no ar, recria os que caem e atualiza versões.
Siglas e termos
Pod, Deployment, ReplicaSet, réplicas, self-healing (autocura), rolling update, requests/limits, probes, labels/selectors.
Para que serve
Manter a aplicação sempre no ar, com o número certo de cópias, e atualizar sem downtime.
Caso de uso
Você pede "quero 3 cópias deste app"; se uma morrer, o Deployment cria outra sozinho.
No ToggleMaster
Temos 5 Deployments (um por serviço), cada um com requests/limits e probes de saúde (/health).
05

Expondo Aplicações e Configurações

Usamos no projeto
Em miúdos
Como os apps se acham (Service), como o mundo de fora entra (Ingress) e como guardar configurações (ConfigMap) e segredos (Secret).
Siglas e termos
Service (ClusterIP/NodePort/LoadBalancer), Ingress, ConfigMap (config não secreta), Secret (senhas), DNS interno.
Para que serve
Dar endereços estáveis, expor por URL de forma organizada e separar a configuração do código.
Caso de uso
O /api chega no serviço A e o /web no serviço B, tudo por um Ingress só.
No ToggleMaster
Usamos todos: Services (ClusterIP) para os 5 serviços, o Ingress (roteia /evaluate, /flags…), e ConfigMaps + Secrets em cada serviço.
06

Gerenciando Estado com Volumes Persistentes

Usamos no projeto
Em miúdos
Pods são descartáveis — se morrem, perdem tudo. Para apps com estado (bancos), usa-se um "HD virtual" que sobrevive (o volume persistente) e o StatefulSet.
Siglas e termos
PV (Persistent Volume) e PVC (o pedido do disco), StorageClass (tipo de disco criado sob demanda), StatefulSet, access modes (RWO).
Para que serve
Guardar dados de forma durável, que sobrevivem a reinícios do pod.
Caso de uso
Um banco de dados rodando como pod, com um disco preso a ele que não some se o pod reiniciar.
No ToggleMaster
É o nosso postgres-targeting: um banco rodando como StatefulSet com um PVC que vira um disco EBS na AWS.
07

Escalabilidade Automática da Aplicação

Usamos no projeto
Em miúdos
O HPA cria e remove pods automaticamente conforme a carga (o uso de CPU) sobe ou desce.
Siglas e termos
HPA (Horizontal — mais pods), VPA (Vertical — pods maiores), Cluster Autoscaler (mais nós), Metrics Server, KEDA (por eventos).
Para que serve
Aguentar picos automaticamente e economizar recursos quando a carga cai.
Caso de uso
A CPU passa de 70% → o HPA sobe de 2 para 5 pods; a carga cai → volta para 2.
No ToggleMaster
Temos HPA no evaluation e no analytics (min 1 / max 2, por CPU), com o Metrics Server instalado — exatamente o que o desafio exigia.
