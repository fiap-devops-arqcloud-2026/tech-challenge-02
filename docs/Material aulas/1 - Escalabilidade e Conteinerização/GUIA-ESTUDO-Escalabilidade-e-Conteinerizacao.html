O que é este módulo?

Diferente dos outros, ele não tem aulas técnicas: é o texto de boas-vindas da Fase 2. Ele apresenta o caminho que você vai percorrer — de containers até balanceamento de carga — e por que cada etapa importa.

Por que ele importa

É o "índice" da fase. Se você entende este roteiro, sabe onde cada assunto se encaixa. E ele termina descrevendo exatamente o projeto integrador — que é o nosso ToggleMaster.

Glossário — os grandes temas da fase

As palavras-chave que o texto usa para descrever a jornada inteira.

ConteinerizaçãoEmpacotar apps em "caixas" (containers) que rodam igual em qualquer lugar.
DockerA ferramenta que popularizou os containers (tema do Módulo 2).
OrquestraçãoCoordenar muitos containers automaticamente. É o papel do Kubernetes.
KubernetesK8sO "maestro" que gerencia os containers em escala (Módulos 3 e 4).
EscalabilidadeA capacidade de aguentar mais usuários sem cair (Módulo 5).
Balanceamento de cargaDistribuir o tráfego entre várias cópias do app (Módulo 6).
EKSElastic Kubernetes ServiceO Kubernetes gerenciado da AWS — onde o nosso projeto rodou.
CDNContent Delivery NetworkRede de servidores espalhados que entregam conteúdo mais rápido.
Reverse proxyUm "porteiro" na frente dos apps que recebe e reencaminha as visitas.
Load balancerO "distribuidor" que reparte as visitas entre as cópias do app.
Projeto integradorO desafio que junta tudo: containerizar → subir no K8s → escalar. É o ToggleMaster.

A jornada da Fase 2, etapa por etapa

O texto descreve 5 disciplinas técnicas + o projeto integrador. Cada ficha mostra o que ela é, para que serve e onde ela aparece no nosso projeto. (Os módulos 2 a 6 têm um guia próprio, igual a este.)

1

Introdução a Containers · Módulo 2

Base do projeto
O que é
Dominar o Docker: imagens, layers, volumes, redes, Dockerfile, Docker Compose e registros (Docker Hub, ECR).
Para que serve
Empacotar aplicações de forma padronizada, segura e portátil.
No ToggleMaster
Os 5 serviços são conteinerizados; o docker-compose.yaml sobe tudo local.
2

Kubernetes Básico · Módulo 3

Base do projeto
O que é
Orquestrar containers em escala: arquitetura do K8s, pods, deployments, services e o comando kubectl.
Para que serve
Fazer o Kubernetes cuidar sozinho de manter os apps de pé, saudáveis e acessíveis.
No ToggleMaster
Todos os nossos manifestos (infra/k8s/) são disto: Deployments, Services, ConfigMaps, etc.
3

Kubernetes Avançado · Módulo 4

Em parte
O que é
Nível produção: deploys Blue/Green e Canary, segurança RBAC, Helm Charts, AWS EKS, e escalabilidade avançada (KEDA, Karpenter).
Para que serve
Operar o Kubernetes com segurança, automação e atualizações sem derrubar o sistema.
No ToggleMaster
Usamos o EKS; os demais (Helm, Canary, KEDA...) ficam como evolução — veja a tabela no README.
4

Escalabilidade nos Servidores · Módulo 5

Conceito aplicado
O que é
Arquitetar para alta demanda: escalabilidade horizontal (mais cópias), CDNs e desacoplamento.
Para que serve
Aguentar picos de acesso sem travar, adicionando capacidade de forma inteligente.
No ToggleMaster
Nosso HPA cria cópias automaticamente; a arquitetura de microsserviços já nasce escalável.
5

Servidores Web e Balanceamento de Carga · Módulo 6

Conceito aplicado
O que é
Servidores como Nginx e Apache atuando como reverse proxy e load balancer, com health check e failover.
Para que serve
Receber as visitas e distribuí-las de forma inteligente entre containers e pods.
No ToggleMaster
Nosso Ingress Nginx é exatamente isto: a porta de entrada que roteia o tráfego para os serviços.
★

Projeto Integrador

É o ToggleMaster
O que é
O desafio que une tudo: containerizar uma aplicação, implantá-la num cluster Kubernetes e configurar deploy, escalabilidade e balanceamento para um cenário real.
Para que serve
Provar, na prática, que você sabe levar um sistema do notebook até a produção na nuvem.
No ToggleMaster
É literalmente o nosso projeto: sistema de feature flags, 5 microsserviços, conteinerizado e implantado no AWS EKS.
