Introdução a Containers (Docker)

A "caixinha mágica" que empacota aplicações — em 6 aulas, com o significado de cada sigla, para que serve e um exemplo real do nosso projeto.

Guia de estudo6 aulas+ glossário de siglas+ conexão com o ToggleMaster

O que é um container?

É uma "caixa" que empacota o app junto com tudo que ele precisa (código, bibliotecas, dependências). Assim ele roda igual em qualquer lugar — acabou o clássico "na minha máquina funciona". O Docker é a ferramenta que popularizou isso.

Por que combina com o nosso projeto

Este módulo é a base do nosso ambiente local. Cada um dos 5 serviços tem um Dockerfile, e o docker-compose.yaml sobe os 9 containers de uma vez. As imagens que fizemos aqui são as mesmas que subiram para o ECR e rodaram no Kubernetes.

Glossário — o significado das siglas

Todos os termos que aparecem nas aulas, em uma linha cada.

ContainerA "caixa" com o app + tudo que ele precisa, isolada e igual em qualquer lugar.
ImagemO "molde" (receita) a partir do qual os containers são criados.
DockerA ferramenta mais popular para criar e rodar containers.
VMMáquina VirtualO jeito antigo, mais "pesado": simula um computador inteiro. O container é bem mais leve.
DockerfileA "receita" em texto que descreve como montar a imagem, passo a passo.
buildO ato de "cozinhar" a receita (Dockerfile) e gerar a imagem.
LayercamadaA imagem é feita de camadas empilhadas — o que acelera builds e economiza espaço.
TagA "etiqueta" de versão de uma imagem (ex.: :latest, :1.0).
Docker HubA "loja" pública de imagens prontas (Nginx, Postgres, etc.).
RegistryregistroUm "armazém" de imagens. O Docker Hub é um; o ECR da AWS é outro.
ECRElastic Container RegistryO armazém de imagens da AWS (onde guardamos as nossas 5).
VolumeUm "HD" ligado ao container para guardar dados que não podem sumir.
Rede (network)A "rede interna" que deixa os containers conversarem entre si por nome.
Docker ComposeFerramenta que sobe VÁRIOS containers de uma vez, a partir de um arquivo YAML.
YAMLO formato de texto (com recuos) usado nos arquivos de configuração.
Multistage buildTruque de Dockerfile: usar um estágio para compilar e outro, enxuto, para rodar.
AlpineUma imagem base minúscula do Linux — deixa a imagem final leve e mais segura.
docker pull/run/ps/stopComandos básicos: baixar imagem / rodar container / listar / parar.

As 6 aulas, uma a uma

Cada ficha tem o mesmo esqueleto: em palavras simples, para que serve, um caso de uso e a conexão com o ToggleMaster.

01

Introdução a Containers

Usamos no projeto
Em miúdos
O que é um container, por que ele resolve o "na minha máquina funciona", e em que ele é diferente (e mais leve) que uma máquina virtual (VM).
Para que serve
Empacotar um app de um jeito que ele rode idêntico no dev, no teste e na produção.
Caso de uso
Rodar o seu primeiro container (ex.: um Nginx) com um comando, sem instalar nada no sistema.
No ToggleMaster
Todos os 5 microsserviços são conteinerizados — é por isso que rodam igual no notebook e na AWS.
02

Imagens e Containers

Usamos no projeto
Em miúdos
A diferença entre imagem (o molde/receita) e container (o prato pronto, rodando). E o Docker Hub, a loja de imagens.
Siglas e termos
Imagem, container, tag, Docker Hub; comandos docker pull, run, ps, stop; ciclo de vida.
Para que serve
Entender que de uma imagem você cria quantos containers quiser — e gerenciar esse ciclo.
Caso de uso
Baixar a imagem oficial do Postgres do Docker Hub e subir um banco em segundos.
No ToggleMaster
Usamos imagens prontas (postgres:16-alpine, redis:7-alpine) e criamos as nossas 5, guardadas no ECR e no Docker Hub.
03

Dockerfile e Build de Imagens

Usamos no projeto
Em miúdos
O Dockerfile é a "receita" para montar a sua própria imagem. E como deixá-la leve e segura para produção.
Siglas e termos
Dockerfile, build, multistage build (separa compilar de rodar), imagens base enxutas (alpine), segurança.
Para que serve
Empacotar o SEU app numa imagem própria — pequena, rápida e sem riscos desnecessários.
Caso de uso
Um multistage build que compila em Go num estágio e copia só o binário para uma imagem alpine minúscula.
No ToggleMaster
Cada serviço tem seu Dockerfile; usamos imagens base alpine (Go e Python) para manter as imagens leves.
04

Volumes e Redes

Usamos no projeto
Em miúdos
Quando um container morre, tudo dentro dele some. Os volumes guardam os dados de forma durável; as redes deixam os containers conversarem entre si.
Siglas e termos
Volume (persistir dados), rede Docker (comunicação por nome), isolamento.
Para que serve
Não perder dados de bancos e organizar a comunicação entre vários containers.
Caso de uso
Um volume guarda os dados do Postgres; uma rede deixa a API achar o banco pelo nome.
No ToggleMaster
No docker-compose.yaml usamos volumes (pg_auth_data, pg_app_data) e uma rede (toggle-net) para os serviços se acharem pelo nome.
05

Docker Compose

É o nosso projeto
Em miúdos
Orquestrar vários containers de uma vez com um único arquivo YAML, em vez de subir cada um na mão.
Siglas e termos
Docker Compose, docker compose up, serviços, redes, volumes, depends_on, healthcheck.
Para que serve
Descrever a aplicação inteira (apps + bancos + cache) num arquivo e subir tudo com um comando.
Caso de uso
Um docker compose up sobe API + banco + Redis já conectados, prontos para desenvolver.
No ToggleMaster
Nosso docker-compose.yaml é exatamente isto: sobe os 9 containers (5 serviços + 2 Postgres + Redis + DynamoDB local) com um comando só.
06

Boas Práticas, Segurança e Troubleshooting

Usamos em parte
Em miúdos
O que separa "só faz rodar" de "entrega robusto": otimizar imagens, cuidar da segurança (do build à execução) e saber diagnosticar quando dá problema.
Siglas e termos
Imagens enxutas, não rodar como root, healthchecks, docker logs, docker inspect, troubleshooting.
Para que serve
Deixar o ambiente mais leve, seguro e confiável — e resolver problemas rápido.
Caso de uso
Um container não sobe; você usa docker logs para ver o erro e corrigir.
No ToggleMaster
Aplicamos parte: imagens alpine enxutas e healthchecks em todos os serviços. Vários problemas reais foram resolvidos lendo docker compose logs.
